ARCHITECTURE / DATA FLOW
Semantic HTML supplies the three-step form; CSS supplies responsive layouts and
accessible focus indicators. app.js reads form values into a normalized profile,
then engine.mjs evaluates six local breed profiles across seven dimensions and
returns ranked fit scores. Input events redraw the live shortlist, completed
results, and comparison bars. A conditional care-plan question appears for more
than five hours away. Without support, all scores are capped at 55, while underlying
scores preserve relative rankings. Selecting a priority changes the weights.
Favorites, answers, quiz step, completion, and comparison IDs persist as a versioned
JSON object in localStorage. Storage errors show a session-only message. A corrupt
record is ignored safely. Comparison metric and saved-only display filter are
transient view controls. No answers leave the browser. Rendering uses only validated
choices and fixed developer-authored breed text, never arbitrary user HTML.

ASSIGNMENT REQUIREMENTS
- State management & persistence: localStorage for quiz and shortlist across reloads.
- Dynamic calculations: weighted scoring and live updates when answers change.
- Interactive visualization: selectable dogs and selectable comparison metric.
- Branching workflow: three steps; long-day answers reveal a care-support question
  and alter score eligibility; changing support removes the cap.
- Responsive layouts: desktop, tablet, and phone CSS breakpoints.
- UI states: initial quiz/empty shortlist; completed results; saved-only empty
  state; storage failure message; toast feedback; comparison-limit feedback.
  Calculations are synchronous and local, so there is no artificial loading delay.

SCORING AND CONTENT LIMITS
This is a transparent educational matching prototype, not adoption eligibility or
medical advice. Numerical activity targets and commitment levels are project
estimates for adult dogs, not AKC scores or individualized prescriptions. Six breed
profiles cannot represent all possible dogs. Individual temperament, age, health,
training, household members, and care arrangements require a real conversation.
Breed source links and weighting details are available in the website itself.

The discovery algorithm combines uncapped lifestyle fit (65%), a fluffy/sleek/open
coat preference (20%), and learned similarity (15%). Similarity compares coat
appearance (50%), size (25%), and activity target (25%). Likes reward similarity;
passes reward dissimilarity. Learning confidence increases over the first three
votes. Lifestyle scores shown to users remain separate and still apply the care
plan cap. This teaching model is transparent and deterministic; it is not evidence
of individual dog compatibility or an adoption decision.

Swipe decisions persist as validated, unique breed/choice records. Each decision
also remembers whether the breed was previously saved, so undo can restore its
prior favorite state. Restart clears learning while preserving favorites. Older
version-1 saved records remain compatible: missing history becomes an empty list
and missing coat preference becomes “any”. The deck exhausts after six dogs and
shows a restart state rather than repeating passed dogs silently. Pointer swipes,
buttons, and keyboard arrows share the same decision handler. Vertical scrolling
is preserved on touch screens.
